# ADR 0010 — Observability conventions
Status: accepted (implemented; a Prometheus endpoint exists on a private management port, but no scraper, alerting or tracing is deployed: see `docs/operations.md`).

* **Logs**: structured JSON (`logging.structured.format.console=ecs`). `CorrelationIdFilter` sets `correlationId` in the MDC (client `X-Correlation-Id` if well formed, else generated), echoes it in the response, and logs **one line per request** (`method path status durationMs`; the **query string is never logged**: it may hold phone numbers or references). The same id is stored on audit events, ledger entries and outbox events, so a request can be followed across all of them. Never log passwords, tokens, secrets or payment-instrument data; events carry no personal data.
* **Metrics** (Micrometer, `/actuator/metrics`, staff-only): `anadepot.operations{operation=reservation.*, payment.*, currency}`, `anadepot.idempotency{result=replayed|race|key_reuse}`, `anadepot.dedup`, `anadepot.outbox.events{result}`, gauges `anadepot.outbox.pending` / `anadepot.outbox.dead` / `anadepot.outbox.oldest.undelivered.age` (seconds), `anadepot.ratelimit{operation,result}`, plus Spring's HTTP/Hikari metrics.
* **Diagnosing without database spelunking**: outbox backlog/dead-letter gauges, `last_error` per event, rate-limit blocked counters, idempotency counters.
* **Scraping**: `micrometer-registry-prometheus` is on the classpath; `/actuator/prometheus` is refused on the public port and served without a token only on a private `management.server.port` (`ManagementSecurityConfig`). Health groups: liveness (process), readiness (database), dependencies (database + object storage).
* **Not yet**: a deployed scraper/alert receiver (rules are proposed in `docs/operations.md`), distributed tracing.
